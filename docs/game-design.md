# 《余字·未寄出的信》玩法设计

## 核心命题

文字不是可复制资源，而是会改变历史的有限物。玩家通过“写入”和“剪下”在当前句、世界回应与整份手稿之间搬运完整意群。每一次获得新词，都必须留下等价的缺口。

## 五回合循环

1. 从字池选择 2–5 个完整意群并排序。
2. 选择句号、问号或引号。句号尝试建立事实；问号保留未决；引号只形成角色话语。
3. 世界生成 40–60 字回应，并标出 3–7 个连续、完整、可剪的意群。
4. 玩家在本轮写入字数预算内剪取 1–2 个意群。
5. 同名字面意群从全文所有位置擦除，只向字池加入一份，并在玩家重新写回前禁止模型复现。

第五次世界回应后仍执行一次剪取，随后进入确定性结算。

## 目标与裁决

目标是“在天亮以前，让她亲手读到并理解那封信”。推进需要依次建立地点、取得信件、阅读信件和理解内容。最终成功必须同时满足：

- 第五轮写成一条句号事实；
- 结构化世界状态为 `understoodLetter: true`；
- 信件和关键记忆没有在最终剪取中被抹除。

问号产生开放结局；关键历史被擦除产生空洞结局；句子成立但事实链不成立时，世界拒绝该句。模型不参与胜负判断。

## 状态不变量

- 意群不可拆分，提交只接受服务端当前字池内的 ID。
- 每轮最多生成一次成功回应，总计最多五次；模型失败不改变版本或回合。
- 剪取候选必须匹配当前回应中的合法 offset，且总字数不超过本轮写入字数。
- 同名字面只进入字池一份，全文擦除按完整意群匹配，不擦除其他词内部的单字。
- 世界擦除同样按完整意群判断：剪掉“那封信”会抹除规范信件事实，剪掉“旧信”不会因为共享单字而删除实体。
- 被禁用意群不得出现在后续模型回应中；玩家写回后解除禁用。
- 所有写入与剪取都检查阶段和单调递增 version，重放请求不会被重复应用。
- 服务端短会话 30 分钟后销毁；完成残稿仅保存在当前浏览器。

## MVP 边界

MVP 只有一个公开剧本、固定五回合、单设备短会话，不包含账号、跨局继承、公开分享、长期云存档、任意字符切割和复杂来源属性。生成失败没有 mock 叙述，玩家可以重试原请求。
